# 事务认领参考讲解（2026-10-22）

本页用于复习 PostgreSQL 的条件更新与事务；**今天未连接数据库，以下只是代码与推演，不能记作实测**。假设存在 `practice_jobs(id, status)` 和 `practice_audit(job_id, action)` 两张练习表。

```sql
BEGIN;

WITH claimed AS (
    UPDATE practice_jobs
    SET status = 'running'
    WHERE id = 'J1' AND status = 'queued'
    RETURNING id
)
INSERT INTO practice_audit (job_id, action)
SELECT id, 'claimed' FROM claimed;

COMMIT;
```

- `UPDATE ... WHERE`：只有 J1 仍是 `queued` 才能认领。
- `RETURNING id`：把真正认领成功的 ID 交给 `claimed`；失败时结果为空。
- `INSERT ... SELECT FROM claimed`：成功才有一条日志；认领 0 行则日志也是 0 行。
- 插入日志若报错，应回滚事务，任务状态也恢复原值。需要由调用方正确处理错误并回滚。
- PostgreSQL 默认 `READ COMMITTED` 下，两个 worker 竞争更新同一行时，第二个会等待第一个事务结束；第一个提交后，第二个重新检查条件，通常返回 0 行；第一个回滚后，第二个可认领并返回 1 行。
