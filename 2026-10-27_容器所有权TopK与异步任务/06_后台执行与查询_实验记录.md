# 2026-10-27 · 后台执行不依赖 GET 查询

目的：验证客户端提交后，即使不调用查询接口，后台仍能独立完成任务并保存终态。

环境：本机 DevDocQA，mock 模型模式；PostgreSQL；Redis TCP 测试替身。不能作为真实 Redis 或真实模型的验收。

实验操作：

1. 用兼容的 RAII 文档提交一个带随机后缀的新问题，避免精确缓存命中。
2. 只发送一次 `POST /v1/questions`，不调用 `GET /v1/jobs/{id}`。
3. 等待 1 秒后，用 PostgreSQL `SELECT` 直接读取任务行；读取过程不执行 UPDATE。

实际输出摘要：

```text
POST HTTP: 202
cached: false
job_id: c35bdd28-2eef-48d4-bd04-5237b6719d73
实验发送的 GET 查询请求数: 0
数据库 status: succeeded
数据库 error: 空
created_at: 2026-10-27 15:36:18.862449+08
finished_at: 2026-10-27 15:36:18.898878+08
```

结论：任务在没有客户端 GET 查询的情况下已经保存为 succeeded。由后台完成路径负责写终态和释放容量，GET 处理路径负责读取状态与结果。

学习记录：此前口述把 GET 查询和保存终态关联在一起，此实验用于纠正这一误区。实验由助手执行，不等于学生已经独立掌握；需要学生重新口述后再判断。
