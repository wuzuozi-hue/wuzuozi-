## 三条路径

### 接收请求

POST /v1/questions → 鉴权/参数/限流/文档与缓存检查 → 缓存未命中时预留名额
→ 创建任务 ID → 数据库 INSERT queued → 入队 → 返回 202 和 job_id。

### 后台执行

调度取出任务 → 条件更新 running → 异步调用 Python → 保存 succeeded/failed
→ 保存成功后归还执行名额和接收容量 → 调度下一任务。

客户端不必发送 GET 来推动后台执行。客户端没收到 202，不会自动撤销已经保存的任务。
当前项目未实现请求幂等：再次被接受的 POST 可能生成新任务，而不是自动复用同问题的任务。

### 查询

GET /v1/jobs/{job_id} → SELECT 当前状态与结果 → HTTP 回复。
HTTP 200、job.status、答案是否有依据是三个层面；GET 200 可以同时返回 failed，
succeeded 也可以返回“资料不足”的有效处理结果。

## 代码入口

本机原始工程路径是 outputs/devdocqa；后端核心阅读文件是 backend/src/server.cpp。
下列为 2026-10-27 阅读时的定位，行号随版本变化；源码工程没有随本学习归档复制。

|位置|功能|
|---|---|
|188 附近 registerHandler /v1/questions|POST 路由，值捕获，投递事件循环，鉴权后进入 question|
|391 附近 question|JSON 类型、长度、空白、UTF-8 校验|
|419 附近 rateLimit|分钟计数键，Lua INCR 和首次 EXPIRE，超限 429|
|438 附近 resolveDocuments|文档 ready、向量签名和集合版本|
|470 附近 submitQuestion|reserve、构造内存任务、数据库插入、成功/失败回调|
|493 附近 enqueue；505 附近 pump|内存队列、超时定时器、执行并发限制|
|514 附近 run|条件认领、异步 HTTP 调用 Python|
|559 附近 finish / persistFinish|重复收尾防护、终态持久化、释放名额|
|按 void job 搜索|GET 查询；读取数据库，不触发任务完成|

容量计数和 shared_ptr 是不同机制。release 调整容量，不删除任务；重复归还会导致漏算。
finishing 表示已经开始收尾；晚到回调应忽略，不能覆盖终态。
普通 bool 检查/设置不能当作跨线程原子保证；项目把相关操作投递到同一事件循环。
异步网络等待允许事件循环处理其他回调；在该循环中直接 sleep 会阻塞同一循环。

## 本地项目运行

需要已有 DevDocQA 工程、其 Python 环境和本地配置。原工程的启动入口为 scripts/start-native.ps1 -Mode mock。
实验脚本 04/05 会从父目录寻找 outputs/devdocqa 或 devdocqa；也可以显式设置：

~~~powershell
$env:DEVDOCQA_ROOT = 'D:\your-path\devdocqa'
~~~

再用已安装 httpx、并能导入项目 smoke_test 配置函数的 Python 运行脚本。
脚本从本地配置读取 API Key，不输出 Key；归档没有保存配置值。
服务地址为 http://127.0.0.1:18880，迁移环境时按实际端口修改脚本。

- 04 是 POST：再次运行会再次提交问题；当前未实现请求幂等。
- 05 是 GET：只查看 JOB_ID 指定的任务；换任务时修改该变量。
- 从归档克隆后不能直接启动完整服务；须准备原工程及依赖。
