## C09 · vector 容量、扩容与迭代器

**一分钟回答：**size 是现有元素数，capacity 是已预留容量。push_back 在末尾构造一个元素；新 size 超过旧 capacity 才需要重新分配。重新分配会使所有旧元素指针、引用和迭代器失效。没有重新分配的尾部插入保留原有元素的引用，但旧 end 失效。标准没有要求每次扩大为两倍；单次扩容可能线性，连续尾部插入是均摊常数时间。[标准草案](https://eel.is/c++draft/vector.modifiers)

**第一层追问：**reserve(10) 后能写 v[9] 吗？空 vector 不行，reserve 不增加 size；要 resize 或添加元素。
**第二层追问：**如何稳定触发扩容测试？在小 vector 上填满实际 capacity，再多插入一个元素，不假定具体增长倍数。

**反例：**“push_back 就等于 malloc 扩两倍”忽略对象构造/移动及实现策略。持有旧元素地址后扩容，再解引用属于错误用法；不要为了观察而执行未定义行为。

**实验：**实验程序输出 reserve/resize 的 size，对填满后再插入的 capacity 变化做断言，不访问旧指针。
**项目关联：**异步回调不能持有会扩容容器中元素的裸地址；先明确对象稳定性和生命周期。
**来源面经：**MJ008、MJ031、MJ032。
**本人验收：**只看代码预测 size；独立改变插入次数，解释哪些句子是标准保证、哪些不是。

## C10 · find 与 operator[]，auto 与迭代器

**一分钟回答：**unordered_map 的键和值角色要先说清。find(key) 返回指向元素的迭代器，没找到为 end，不插入；检查成功后 it->first 是键，it->second 是值。operator[] 在键不存在时插入元素；对 int 值会初始化为 0，因此适合计数，但不适合“只查询”。auto 让编译器从初始化表达式推导静态类型，不是运行时动态类型。[下标语义](https://eel.is/c++draft/unord.map.elem)

**第一层追问：**能对 end 解引用吗？不能；必须先比较。
**第二层追问：**前缀和为什么存次数而有时存最早下标？容器相同不代表值的语义相同；计数题累加匹配次数，最长长度保留最早位置。

**反例：**用 m[need] == m[current] 判断键是否存在，会插入新键，还混淆“键存在”和“值相等”。
**实验：**m 初有两键；find 缺失键后 size 不变，m[缺失键] 后 size 增一，值为 0。
**项目关联：**任务查询不能因为 ID 不存在就偷偷制造默认任务；查询失败应明确返回。
**来源面经：**MJ001、MJ020。
**本人验收：**改成 const 容器后选择可用查询 API；说明返回值类型和修改的对象。

## C04 · 智能指针管理所有权

**一分钟回答：**unique_ptr 表示独占所有权，不能复制，可移动。shared_ptr 共享控制块的所有权，最后一个强引用消失时通常销毁所管理对象；weak_ptr 观察，不延长强引用生命周期，通过 lock 尝试取得 shared_ptr。reset 只放弃当前持有关系，不保证对象立刻销毁；要看是否还有其他拥有者。shared_ptr 的引用计数同步不等于被管理对象线程安全。[观察接口](https://eel.is/c++draft/util.smartptr.shared.obs)

**第一层追问：**两个 shared_ptr 指向同一对象，p.reset 后 q 能否用？只要 q 仍有效可以。
**第二层追问：**use_count()==1 能不能当锁？不能，多线程下计数快照不能证明无人并发访问对象，也不建立需要的同步。

**反例：**从同一个裸指针分别构造两个独立 shared_ptr，会建立不相干的控制块，可能重复释放；不要这样“增加计数”。
**实验：**程序在单线程中观察复制、reset、weak.lock 和销毁时机；不把此输出当并发保证。
**项目关联：**[task] 值捕获使 task 所有权继续存在，但不会自动释放业务 slots 名额。
**来源面经：**MJ003、MJ008、MJ029、MJ032。
**本人验收：**画两个 shared_ptr 与一个对象的关系；指出是哪一个对象在 reset 时改变。

## C06 · std::move 与移动构造/赋值

**一分钟回答：**std::move 是转换表达式值类别的工具，本身不搬资源。后续调用的构造函数或赋值运算符才决定复制还是移动。新建 b(std::move(a)) 是初始化 b；已有 b 后 b=std::move(a) 是赋值。unique_ptr 的成功移动会转移所有权并让源为空。不能由此推断所有自定义类或所有标准库对象移动后都为空。

**第一层追问：**只写 std::move(a); 对 a 有何资源效果？没有执行移动构造/赋值就没有因此搬走资源。
**第二层追问：**const 对象做 std::move 一定移动吗？不一定；转换不能去掉 const，可能匹配复制或无法编译。

**反例：**把“左边出现变量名”当区分依据不够；要判断那一刻是否正在创建对象。
**实验：**用 unique_ptr 分别演示移动构造和赋值，检查源为空、目标持有值。
**项目关联：**将独占资源交给异步任务时明确所有权转移，别继续解引用移走后的源。
**来源面经：**MJ019、MJ031、MJ033。
**本人验收：**对两行分别标出构造/赋值，独立改为普通复制并解释编译失败原因。

## C13 · lambda 捕获和异步生命周期

**一分钟回答：**[x] 把可复制的 x 保存到闭包中；[&x] 引用外部对象，不延长其生命周期。shared_ptr 按值捕获会多一个拥有者；unique_ptr 可通过 [p=std::move(p)] 移动捕获。捕获方式应按回调执行时间和谁拥有资源决定，不能为了少复制默认全用引用。

**第一层追问：**创建回调后外部 shared_ptr reset，回调还可访问对象吗？按值捕获的拥有者仍在就可以。
**第二层追问：**对象保存一个捕获自身 shared_ptr 的回调，有什么风险？可能形成所有权环，考虑 weak_ptr 与 lock，并处理对象已销毁的情况。

**反例：**返回一个引用捕获局部变量的 lambda，外部调用时局部变量已经结束生命周期。
**实验：**闭包存进 std::function；外部 reset 后仍执行；清空 std::function 才释放最后拥有者。
**项目关联：**C++ 回调不应捕获已返回函数栈上的短命引用；对象存在与任务完成是两件事。
**来源面经：**MJ003、MJ018、MJ020。
**本人验收：**独立画出闭包、shared_ptr 控制块、Task 三者；无需记住术语才能解释清楚。

## C03 · RAII 与一次释放

**一分钟回答：**RAII 将资源管理放进对象生命周期：构造成功建立资源拥有关系，析构结束时释放。资源不限于内存，还包括锁、文件和连接。局部对象在正常退出、return、异常展开时析构；不保证强杀进程后执行。一个守卫应明确是否仍拥有资源，避免手动释放后析构再次释放。

**第一层追问：**return 会跳过局部对象析构吗？正常返回不会。
**第二层追问：**有两个复制的守卫都负责同一名额会怎样？可能重复释放，应禁复制或设计明确的共享/移动所有权。

**反例：**容量计数减为 0 不代表 Task 已销毁；Task 析构也不自动意味着业务容量已经正确归还。
**实验：**简单 Guard 在构造增加计数，析构减少；普通作用域、提前 return、抛异常分别验证最终为 0。
**项目关联：**审查 reserve/release 的失败路径；不要未经分析把现有异步跨线程路径直接换成局部守卫。
**来源面经：**MJ023、MJ032。
**本人验收：**独立补一个异常分支并解释为什么仍只归还一次。
