# 2026-10-21：按任务 ID 追踪故障（模拟日志）

下面是**教学用的模拟记录**，不是今天真实运行 DevDocQA 得到的日志。状态码和错误名称参照当前项目代码；用 `job_id` 把提交、后台处理、查询连起来。

## 场景 A

```text
16:35:00 POST /v1/questions -> HTTP 202  {"job_id":"J21"}
16:37:00 job=J21 kind=question outcome=job_timeout
16:37:05 GET /v1/jobs/J21 -> HTTP 200  {"status":"failed","error":"job_timeout"}
```

1. 第一次提交是否被接受并产生任务 ID？
2. `GET` 返回 HTTP 200，能不能据此说 AI 回答成功？
3. 哪个字段指出失败原因？

## 场景 B

```text
16:39:00 POST /v1/questions -> HTTP 503  {"error":"queue_full"}
```

4. 这次请求有没有拿到可轮询的任务 ID？
5. `queue_full` 指向哪一层的容量限制：数据库连接池、AI 任务容量，还是 TCP 接收缓冲区？

实际排障时还要核对时间戳、任务 ID、数据库中的任务状态，以及 Worker 日志；不能只凭一条 HTTP 状态推断完整原因。
