## 条件认领

```sql
UPDATE practice_jobs
SET status = 'running'
WHERE id = 'J7' AND status = 'queued'
RETURNING id;
```

两个 worker 先后执行且第一个成功提交：第一个返回 1 行，第二个返回 0 行。SQL 字符串使用单引号；双引号用于标识符。写在 `.sql` 文件中的答案说明要加 `--`，否则 `1.1`、`2.0` 等裸文本会造成语法错误。

## 事务与恢复

- 同一事务内先插入任务 `J8`，再插入 `K8 → J8`；第二步失败并回滚，**两条新记录都不存在**。
- 如果两条均提交成功，但尚未入内存队列就崩溃，数据库中 `queued` 的 `J8` 仍在；启动后可重新读出并入队。
- 当前 DevDocQA 启动时保留并重新装入 `queued` 任务；把旧 `running` 任务标为 `failed`，错误为 `backend_restarted`；把 `processing` 文档标为 `failed`，删除其未完成片段。这是代码走读结论，不是今日故障注入结果。

## 幂等键唯一约束

练习表的约束应为 `UNIQUE (client_id, idempotency_key)`。`A`、`B` 是调用方的示例值，不是表的列名。同一调用方用同一键且请求摘要相同，应复用旧任务 ID；摘要不同应拒绝。当前 DevDocQA 还没有实现这张练习表或请求幂等键，重新提交仍可能生成新任务 ID。
